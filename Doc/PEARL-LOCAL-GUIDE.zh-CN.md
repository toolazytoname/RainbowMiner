# 小兔头：本地 Pearl 操作说明

## 两个工程，一个入口

RainbowMiner 管理工程负责开始、停止、温度和功率保护、为别的 GPU 任务让路，以及到首次打款门槛后停止。soat-miner 工程包含真正计算的 CUDA 内核，可以自己编译和修改。日常只用桌面「珍珠挖矿」的开始／停止按钮，不需要先后手工打开两个程序。

本版默认计算后端是已验证的开源 SOAT。它在本机 220W 稳态 A/B/A 测试中，比原始源码版本提高约 9.7%，原版前后波动约 0.58%；相同新二进制通过了独立矿池测试：3 接受、0 拒绝。这个比较针对原始 SOAT，不能说成比 KRig 快 9.7%或收益提高 9.7%。管理入口接管后的实机验收已通过：2 接受、0 拒绝，约 3 秒为新 GPU 任务让路、约 5 秒普通停止，功率恢复与截止时间保留。控制台截图也已核对，实际点击开始／停止按钮的另一轮测试也已通过（约 2 秒停止）。

选择开源后端还保留了计算源码的控制权。KRig 原生 SSL 在本地负向测试中接受了自签证书；改走严格校验的本机转接地址时，它又启用了 3% 开发者费。因此本版不会默默改用这个 KRig 收费路径。完整 RainbowMiner 的支持时段循环也不在这个本地单次管理入口中运行。

## 手动走一次

1. 先结束游戏、ComfyUI、LM Studio 等 GPU 任务。普通 CPU 任务可以同时运行。
2. 打开桌面珍珠挖矿控制台，选运行时限，点「开始挖矿」。仍然受原体验截止时间和首次门槛约束。
3. 等待初始化。控制台显示「开源 CUDA 内核」和 `T MAC/s`，并显示温度、显卡功率、接受与拒绝份额。这个算力单位表示每秒万亿次乘加计算，不是币数。
4. 点「打开矿池收益页」，输入自己的公开 PRL 地址查看累计与打款；也可以打开 `D:\Apps\KRig\Runtime\体验进度.html`。
5. 结束时点「停止并恢复功率」。确认已停止、进程退出、原功率恢复。关闭面板本身不会停止挖矿。
6. 点「查看运行记录」会打开本轮文件夹。`session-result.json` 是停止结果，`selected-profile` 中有计算日志、温度记录和 `tls-status.json`。

也可以进入 `D:\Projects\toolazytoname\RainbowMiner`，运行：

```powershell
.\Scripts\PearlExperience\Manage-Pearl.ps1 -Action Status
.\Scripts\PearlExperience\Manage-Pearl.ps1 -Action Start -Minutes 60
.\Scripts\PearlExperience\Manage-Pearl.ps1 -Action Stop
```

Source 的 `T MAC/s` 与 KRig 的 `TH/s` 保留各自原始口径，不做没有依据的跨软件换算。平时主要看温度是否稳定、拒绝份额是否为零、池内余额与真实打款记录。

## 自动停止与恢复

使用原来的公开 PRL 地址、Kryptex 矿池和结算模式，不会因为换计算程序而丢掉池内余额。已确认与待确认之和达到门槛，或出现打款记录，就停止 GPU；待成熟和打款不需要继续挖。等待阶段最多查询 12 小时，停止按钮也能结束查询，不会改变矿池余额。

原截止时间从 `D:\Apps\KRig\Runtime\payout-experience.json` 延续，重开不续期。CLI 单次最多填写 2160 分钟（36 小时），实际仍会被原截止时间截断；不能靠这个参数重新获得 36 小时。手动停止、温度保护、其他 GPU 任务和运行异常都会结束本轮，不自动重开，也不随开机挖矿。

本轮最高 220W。核心／热点／显存结温保护为 80／100／96℃；没有手工调频、电压、风扇或改 Defender。正常停止后恢复本轮开始前的功率上限。若其他程序改变了功率，则保留它的设置并记录。

恢复程序只处理本轮记录的进程，并核对创建时间、路径和校验值。若进程未确认退出，会显示「停止未完成」并保留低功率，避免误称停止或恢复。面板会禁用再次开始，仍可查看记录并执行停止。

矿工命令里的 `127.0.0.1` 是本机内部转接；真正向外连接前会核验证书链和矿池域名。程序只用公开收款地址，不读取助记词、私钥或钱包密码，也不自动换成 USDT。

### 等待新任务时，为什么速度会变成 0？

矿池有时会暂时没有可用的新任务。这时显卡空闲、功耗和温度下降是正常现象。
新版在已经开始过计算后，会在等待期间继续报告 0 速度；新任务到来后恢复正常。
界面不会继续把之前的速度当成当前速度。每条统计都有独立时间，单纯不断写告警
不能让旧统计一直有效。启动时仍保留原有 90 秒首次有效统计保护。

这次更新只改了主机端统计与显示校验，没有修改 CUDA 计算内核和证明算法。
原来约 9.7% 的测试提升仍只指保存的内核方案相对原始源码基线，不代表兑币收益。
